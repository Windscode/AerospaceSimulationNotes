# 项目评级规则

## A：值得深入复现

满足多数条件：

- 领域高度相关。
- 文档清楚。
- 能本地编译或运行。
- 示例有验证价值。
- 代码结构值得学习。
- 可能直接服务自己的项目。

## B：值得阅读

- 有学习价值。
- 不一定适合直接集成。
- 可作为理论或实现参考。

## C：只做索引

- 方向相关，但价值暂不明确。
- 暂时不投入时间。
- 等未来有需求再看。

## D：不推荐

- 无法运行且文档差。
- 长期无人维护。
- 技术路线明显不适合。
- 授权或合规风险较高。
- 内容看似相关但实际只是玩具 demo。

## 评级时必须避免

不要因为项目 Star 多就判为 A。Star 只能说明热度，不能说明工程可用性。
